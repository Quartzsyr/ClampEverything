# 实现与维护说明

## 分层

`ClampCore` 只依赖 Foundation，包含内容、摆放、分组、存储、引用身份与串行复制队列。`ClipItem` 保存内容引用或副本及标签，`ClipPlacement` 保存显示器、位置、尺寸和模式，`ClipGroup` 保存单层项目组织关系。撤销状态使用 `removedAt`，7 天到期；图片引用和剪贴板图片副本通过 `bookmark` / `assetName` 区分。

原生应用层的 `ClipStore` 在 MainActor 上维护可观察状态、导入、行为适配、缩略图和复制结果。`WindowManager` 管理每屏接收入口和每项面板，使用显示器 UUID 持久标识屏幕。`CardModel` 的悬停、保持展开和交互锁是会话状态，靠边临时展开不写入资料库。

AppKit 桥接视图分别处理移动把手、内容拖出和复制接收区。内容拖出实现 `NSDraggingSource`，源操作掩码只包含 `.copy`。Quick Look 通过嵌入 `QLPreviewView` 的独立窗口实现，遵循系统预览视图生命周期。

## 保存与失效处理

JSON 版本为 1，日期使用 ISO 8601。写入先保存上一份快照，再以 `.atomic` 更新当前元数据。变化后约 250 ms 合并保存，关键导入及退出立即保存。读取错误会将资料库置为只读状态。

文件引用使用非沙盒持久书签；解析不自动挂载离线卷，也不弹出隐式选择窗口。打开后刷新过期书签和位置。引用失效显示卡片内提示，重新关联仅替换引用，不改原内容。此版本不配置 App Sandbox；未来上架沙盒版需补充安全作用域与授权生命周期。

恢复区清理先成功保存移除元数据后的资料库，再删除仅由应用管理且没有其他引用的资源。所有内部资源名检查路径穿越。恢复元数据快照并不等于完整资源备份。

## 文件夹复制

`FileCopyQueue` 是串行 actor。每项先复制到目标中的独有 `.clamp-copy-UUID` 暂存位置，再尝试原名或编号名称；目标存在时继续编号，不覆盖。落盘失败时只清理本次拥有的暂存位置。目标与源目录的包含关系按解析符号链接后的路径检查。

每项返回源路径、实际目标或错误文字；界面显示成功、失败、完成数量及重试入口。停止任务只阻止后续项。突然断电或强制结束可能留下隐藏暂存文件，应确认名称与来源后手动处理；本版本不扫描用户目录清理未知文件。

## 屏幕与焦点

每张卡片单独使用 `.nonactivatingPanel`，限定窗口尺寸，键盘编辑通过普通窗口进行。挂断屏幕时保留原位置并归入主屏；用户重新摆放后取消旧屏自动恢复。坐标以可用区域的相对位置保存，渲染时限制在可见范围。

全屏检测使用前台应用公开窗口几何，并订阅 Space 变化，每 2 秒作补充检查。此为保守判断，覆盖整块显示器的普通无边框窗口也可能被认为是全屏；不使用私有 API。快捷键未注册时不占用系统组合。

## 开发入口

构建：`scripts/build-app.sh`；测试：`scripts/test.sh`；设计截图：`scripts/export-design.sh`。构建在系统临时目录完成签名后替换包，保留上一个生成包。没有引入外部包、浏览器运行时或图像生成服务。
